# Задачи Jira и работа агентов

Jira хранит постановку, критерии, приоритет, статус и отчёты. GitHub — код и PR.
Внутренние задачи не дублируются в Linear, GitHub Issues или файлах.

Проект Jira: SCRUM, метка направления: pc-keyboardswitcher.
Адрес: https://crystalcore.atlassian.net. Эти значения также указаны в registry.json
приватного штаба itmaxk/hq. Общие правила читать через локальную папку HQ в Orca.
При общем Jira-проекте фильтровать по проекту И метке направления.
Не считать все задачи проекта задачами KeyBoardSwitcher.

## Доступ и исполнение

1. Через подключённый Jira MCP прочитать задачу, комментарии, связи, текущие
   transitions и соответствующий PR. Выполнение должно быть поручено владельцем.
2. Найти существующий worktree/PR. Для новой работы создать Orca worktree
   от основной ветки, включив ключ Jira в имя. В текущем CLI нет Jira-флага:
   ключ/URL записать в комментарий карточки; --issue относится к GitHub,
   --linear-issue не применять.
3. Прочитать AGENTS.md и CONTEXT.md, перейти в In Progress через актуальный
   transition ID, выполнить поручение и проверки.
4. В заголовке PR указать настоящий ключ Jira, в теле — URL. Добавить remote link
   Jira → PR через jira_create_remote_issue_link, предварительно проверив дубли.
5. Через jira_add_comment записать результат, коммиты, PR, проверки,
   ограничения и рабочую копию для продолжения. Прочитать запись обратно.
6. Перейти в In Review и передать PR владельцу. Самостоятельно не сливать.

## Статусы

Использовать реальный workflow проекта. Для проверенного SCRUM:
To Do → In Progress → In Review → Done; отмена — через переход Cancel.
Backlog — To Do без pc-ready, Ready — To Do с pc-ready.
Блокировка — pc-blocked с причиной, исходный статус сохраняется.
При старте снять pc-ready, после устранения препятствия снять pc-blocked,
сохраняя остальные метки. Метки не разрешают автозапуск.

Статусы ведёт агент через Jira MCP. Не включать конкурирующие автопереходы
GitHub/Smart Commits. Ключ PR может связать development-данные при настроенной
интеграции, но сам по себе не является приёмкой или переходом в Done.
Done требует приёмки владельца, выполнения всех критериев и принятого merge.

Перед записью перечитать Jira и факты PR. При неопределённой ошибке проверить
историю, комментарии и ссылки до повтора. Не выдумывать write-id для Jira.
Если результат записи не удалось подтвердить, сообщить об этом, не создавать
дубликат; можно сохранить временный черновик с ключом задачи.

Планы штаба хранят результаты и ссылки, а не вторую таблицу статусов.
При отсутствии доступа к приватному HQ соблюдать этот контракт и читать
реальную Jira-задачу; не угадывать project key и не публиковать личный контекст.
