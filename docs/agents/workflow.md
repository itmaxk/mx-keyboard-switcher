# Задачи Linear и работа агентов

Команда: **Personal Corp / PC**. Проект: **KeyBoardSwitcher**.
Linear хранит постановку, критерии, приоритет, статус и отчёты. GitHub хранит
код и PR. Внутренние задачи не дублируются в Jira, GitHub Issues или файлах.

## Контекст и доступ

Общие правила и реальные идентификаторы workspace/project находятся в приватном
штабе `itmaxk/hq`, в `AGENTS.md` и `registry.json`. Штаб открывается как отдельный
репозиторий Orca; относительный путь из worktree к нему не гарантирован.
Если штаб недоступен, читать задачу через настроенный Linear и соблюдать этот
контракт; не угадывать идентификаторы и не переносить приватное содержимое в PR.

В доступной версии Orca есть `linear` CLI. Перед первым вызовом прочитать
навык `orca-cli` и справку `linear --help`. Получить реальную команду/workspace
через `linear team list`, а проект — через `linear project list`.
Если подключение не настроено, сообщить об этом; временный локальный черновик
не считается задачей, сохранённой в Linear.

## От задачи до PR

1. Прочитать задачу полностью: результат, границы, критерии, зависимости,
   комментарии, связанные PR. Убедиться, что выполнение поручено владельцем.
2. Найти существующий worktree/PR; возобновить его. Для новой работы создать
   Orca worktree от основной ветки с `--linear-issue` и настоящим ID задачи.
   Имя ветки содержит ID, например `pc-123-short-description` (пример, не реальная задача).
3. Поставить In progress и записать начало. Выполнить задачу и подходящие проверки.
4. Подготовить PR по шаблону; для полностью закрываемой задачи указать
   `Closes PC-<номер>` и настоящий URL Linear. Для частичной работы —
   информационную ссылку `Related to PC-<номер>` без автоматического закрытия.
5. Записать в Linear: результат, PR/коммиты, проверки, ограничения и следующий
   шаг. Прочитать обновление обратно. В отчёте указать ветку/worktree для продолжения.
6. Передать PR на приёмку. Самостоятельно не сливать и не выпускать релиз.

## Статусы и сбои

Путь задачи: Backlog → Ready → In progress → In review → Done.
Blocked требует описания причины и необходимого действия; Canceled — решения владельца.
Ready не запускает агентов автоматически.

Настроенная интеграция GitHub переводит готовый PR в In review, принятое
слияние в main — в Done. Draft PR, зелёный CI и закрытие без merge не означают Done.
При нескольких PR задача готова только после выполнения всех критериев.
Перед ручным обновлением прочитать состояние Linear и PR, чтобы не спорить с
автоматикой. Завершение карточки Orca не является приёмкой задачи.

Если запись в Linear не подтверждена, не объявлять синхронизацию успешной:
перечитать объект и последние комментарии до повтора, сохранить возвращённый
Orca write-id при неопределённом результате. Не создавать второй объект вслепую.
Недоступность Linear не означает отсутствие задач. Планы штаба ссылаются на
Linear и не ведут отдельные текущие статусы.
