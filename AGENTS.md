# MX Keyboard Switcher — правила для агентов

## Live-тесты X11 и запуск бинаря — ТОЛЬКО на изолированном дисплее

Тесты `crates/mxks-platform/tests/x11_live.rs` и сам демон mxks инжектят
нажатия клавиш через XTEST. На рабочем дисплее (`:10`) эти события попадают в
окно с фокусом — в терминалы пользователя летят фантомные Shift+Tab, Ctrl+C и
буквы, ломая чужие сессии.

Поэтому:

- **Запрещено** запускать `cargo test ... --test x11_live -- --ignored` или
  собранный бинарь mxks с `DISPLAY=:10` (или любым дисплеем реального рабочего
  стола).
- Live-тесты запускать **только** через `scripts/run-x11-live-tests.sh` — он
  поднимает отдельный Xvfb, настраивает раскладки us,ru и выставляет
  `MXKS_TEST_DISPLAY`. Без этой переменной тесты намеренно падают
  (см. `require_isolated_display()` в `tests/x11_live.rs`).
- Для ручного запуска демона в разработке — тоже отдельный Xvfb/Xephyr,
  не рабочий дисплей.


## Порядок работы

1. Прочитать этот файл, [CONTEXT.md](CONTEXT.md) и задачу Linear.
2. Изучить относящиеся к задаче исходники и тесты; сохранять чужие изменения.
3. Выполнять порученную задачу в отдельном worktree через Orca; при повторном
   запуске сначала искать существующую ветку и PR.
4. Проверить результат, открыть связанный PR и записать отчёт в задачу Linear.
   Слияние и релиз выполняются после решения владельца.

## Agent skills

- Трекер: **Linear**, команда `Personal Corp` (`PC`), проект `KeyBoardSwitcher`.
  Подробный контракт: [docs/agents/workflow.md](docs/agents/workflow.md).
- GitHub Issues, Jira и локальные Markdown-задачи не являются внутренней очередью.
  Если используемый общий скилл предлагает другой трекер, применять выбранный
  здесь Linear; не создавать задачу-дубль ради выполнения скилла.
- Контекст домена: [CONTEXT.md](CONTEXT.md). Новые архитектурные решения
  сохранять в `docs/adr/` по мере появления; пустые ADR не создавать.
- Исполнитель читает нужный скилл штаба через его `AGENTS.md`. Статусные обзоры
  и недельные планы не разрешают запускать реализацию.

## Проверки

Изменения Rust: `cargo fmt --all --check`, релевантные тесты, затем
`cargo clippy --workspace --all-targets -- -D warnings`. Общий набор:
`cargo test --workspace`; сборка: `cargo build --workspace`.
CI также проверяет Windows и macOS. Успех на Linux не выдавать за ручную
проверку других платформ. Для документации достаточно проверки ссылок и diff;
демон и live-тесты для неё не нужны.

Документация для пользователя: README.ru.md и README.md. Не переносить в
публичный репозиторий личные данные и содержимое приватного штаба.
